FOUNDATIONS / 01

Quick start

Use the Windows desktop app for Jev, local logs, Episode labeling, and datasets. The static website is a guide and download entry point.

  1. 01

    Launch and sign in

    Open the Windows x64 app and sign in with a local workspace account. If an account still uses a public demo password, change it to a private password before adding AI keys.

  2. 02

    Configure AI access

    Open Workspace account from the account avatar. Add the Jev key for tool decisions; add the DeepSeek key for parameter extraction and explanations of unsupported requests. Keys are encrypted per account in local runtime data.

  3. 03

    Load a semantic IFC model

    Use the included Duplex IFC or choose Append model. For AI property questions, use IFC: GLB and glTF provide geometry and metadata, but do not become full IFC semantic models.

  4. 04

    Make a first request

    In the Jev prompt at the bottom of the workbench, enter List all door entities. Press Enter. Check the returned list and select a result to show it in the model when a visible mesh exists.

The included Duplex IFC is SophonBIM's default model. The file comes from That Open Company's public web-ifc regression fixture ↗, distributed under MPL-2.0.

Keyboard tip

Enter sends the prompt. Shift+Enter adds a line break. A specific action and a named target are easier to validate than a long multi-part command.

FOUNDATIONS / 02

Workspace and models

The tree, 3D viewport, inspector, and ribbon work together. Jev uses this current project state rather than a hidden sample model.

Import and select

Choose Append model for IFC, GLB, or glTF. Select in the tree or viewport; Ctrl-click extends the selection. For external-buffer glTF, add its .gltf and referenced .bin files together.

Inspect in 3D

Use Section box for clipping and Measure for two surface points. Double-click an object to focus it. The inspector shows identity and properties for selected elements.

FOUNDATIONS / 03

Coordinate a project

The manual workflow remains available whether or not AI keys are configured.

  1. 01

    Create a test

    Open Coordination → New test. Select two model, selection-set, or all-element scopes. Choose Hard for contact/intersection or Clearance for a threshold in millimetres.

  2. 02

    Run and inspect

    Choose Run test. Select a clash row and double-click to focus the pair. Use the status control to mark review progress, or create an issue linked to that result.

  3. 03

    Capture and deliver

    Save a viewpoint with the current camera and visibility. In Output, export the coordination report, clash CSV, viewport snapshot, or portable project file.

After model changes

Imported or transformed geometry and edited tests can mark clash results stale. Rerun the test before treating those results as current.

AI AGENT / 01

How Jev + DeepSeek work

The composite agent has a decision stage and, when needed, a parameter stage. Both operate within SophonBIM's actual tool and project context.

01Your requestPlain English in the Jev prompt
→
02Jev decisionOne available platform action
→
03DeepSeek if neededParameter extraction or unsupported-request explanation
→
04Local validationTarget, value, and action checks
→
05BIM resultAction trace and visible output

What Jev decides

Jev chooses one bounded action from the current catalog, then resolves model, element, clash, or issue targets from the open project. It can choose Not currently supported when no single action covers the whole request.

When DeepSeek joins

DeepSeek extracts missing free-form parameters for compound filters, names, descriptions, or issue edits. It may also briefly explain an unsupported request, without executing an action. Structured extraction follows a request-specific JSON schema with a 20-second timeout; extracted values are validated locally before execution.

What the trace means

Completed Jev decisions appear as the workflow runs. A parameter card appears after validated DeepSeek extraction. An invalid or timed-out plan does not mutate the project. Tool classes exist, but the current Action Gate policy is allow_all; the class labels are not a human approval gate.

AI AGENT / 03

Prompts you can try

Use these as one-action examples. Replace names and IDs with those shown in your own project.

IFC / JEVList all door entities.

Lists semantic doors in the selected IFC model.

COMPOUND QUERY / JEV + DEEPSEEKFind the doors marked A101, A102, or B101.

Extracts a value list and checks it against IFC properties. This example is available in the bundled Duplex IFC.

RANGE + UNITS / JEV + DEEPSEEKFind second-floor casement windows between 800 and 900 millimetres wide.

Extracts floor, family, and width range, then normalizes units. The required property fields must exist in the active model.

COORDINATION / JEV + DEEPSEEKCreate MEP clearance between Structure.ifc and MEP.ifc at 50 mm and run it.

Creates and runs one test when those two models are in the current project.

ISSUES / JEV + DEEPSEEKCreate an issue for clash result 2 titled Resolve kitchen door clearance. Description: Check the wall and door clearance.

First create and run a clash test in your project. Use this prompt only if that test actually produces result 2; the fresh default project has no clash results. Extracted issue text is validated before creation.

SUMMARIES / JEVCount issues by status.

Summarizes current project issues by their actual statuses.

Prompt pattern

Name one action, the target, and any needed values. First create and run a test named Duplex clearance test; if it produces result 2, you can ask Show clash result 2 from the Duplex clearance test. Then issue a separate request to change its status.

LEARNING / 01

Activity Log: inspect the action trace

Activity Log is the workspace's chronological view of human, agent, and system actions. Use it to see what happened before deciding whether an Episode contains useful task evidence.

Before you begin

Use the Windows desktop app or the local service and sign in. The public website cannot read your local Activity Log. For a first trace, open the included Duplex IFC and perform one clear action, such as List all door entities. with configured Jev access, or select an element manually.

  1. 01

    Open the log

    Click Activity Log in the workbench's top navigation. The page loads records from the local service and initially scopes the Project filter to the current project when that context is available.

  2. 02

    Check delivery before interpreting an empty stream

    Read the delivery message above Activity stream. A recently recorded action may still be in this account's local outbox. Click Refresh to retry delivery and reload the stream; if needed, return to the signed-in workspace and reconnect the local service.

  3. 03

    Narrow the event set

    Choose a Project and Account, then an Actor: Human users, LLM / agents, or System. Choose an Outcome to focus on completed or problematic actions. The Search field matches an action name, source, status, and sanitized structured fields.

  4. 04

    Read the stream and summary

    The counters show matching versus total loaded events, human and agent events, and Needs attention. Each row shows its action, source, outcome, gate class, and time. Select a row, or focus it and press Enter, to open its detail pane.

  5. 05

    Inspect the evidence

    In the detail pane, compare Outcome with Gate and Decision, then inspect sanitized Context, Input, and Result. Use the Session and Record ID to distinguish nearby events. An agent decision and the resulting BIM operation may appear as separate rows.

  6. 06

    Move from events to a task Episode

    Use Episode labeling at the top of the log page to inspect grouped runtime actions. Confirm that the action sequence and outcome match one task before labeling it. A log row alone is not a validated training example.

How to interpret Activity Log fields
FieldWhat it tells you
Action · timeThe structured operation name and when it was recorded. Search the action name to follow repeated operations.
Actor · sourceWhether a human, an LLM/agent, or the system initiated the event, and which application channel reported it.
OutcomeThe recorded result status, or the decision if a result status is absent. “Needs attention” counts failed, error, timeout, denied, and confirmation-required outcomes.
Gate · decisionThe action classification and gate result. The current allow_all policy does not make these labels a human approval record. not_applied on a direct human action means the gate was not used; it is not a failure.
Account · source trustThe authenticated account associated with the event and whether its action source was client reported or unverified legacy data. “Client reported” is not independent proof of intent.
Session · Record IDIdentifiers for following related events and locating one record; these help connect a trace to its later Episode.
Context · Input · ResultBounded, sanitized structured evidence. Passwords, prompts, paths, and other sensitive values are redacted before persistence, so their full text is not available here.

The page searches only the latest 1,000 loaded log entries. Activity Logs are stored locally; the current account's unsent events are retried from a browser-local queue. An empty filtered view can mean no matching event, a pending upload, or a different project/account filter. The log itself is read-only.

LEARNING / 02

From activity to labeled Episodes

Episode Labeling turns a sequence of runtime events into a human-checked account of one task. The app stores edits as revisions alongside immutable raw logs; it does not retrain the model automatically.

  1. 01

    Open the runtime queue

    Click Episode Labeling in the workbench or from Activity Log. In the Episode labeling tab, keep Environment on Runtime. Search by action or Episode ID and filter State to Unlabeled, Draft, Submitted, Reviewed, or Excluded.

  2. 02

    Read one task timeline

    Select an Episode in the left queue. Check its time window, account, session, source trust, boundary confidence, and attention flags. The center timeline shows action, actor, source, gate, and outcome for semantic steps; enable Show observer events when navigation or selection context matters.

  3. 03

    Fix the boundary, or exclude weak evidence

    Use Split after where two tasks were joined, or Merge previous for adjacent parts of the same task. If the record is not a usable task, select a reason such as insufficient evidence or test data and click Exclude. Otherwise click Confirm boundary.

  4. 04

    Describe the intent

    In 1 · Intent, choose a taxonomy category, enter the target type, add only supported constraints, and set High, Medium, or Low confidence. Check the generated goal. For a door listing, a suitable intent is ifc.type-query with target IfcDoor.

  5. 05

    Label outcome and step value

    Choose Success, Partial, Failure, or Unclear. For every outcome except Unclear, select the timeline step(s) that support the result. Label every semantic step as Necessary, Supporting, Redundant, Erroneous, or Unclear. Optional JEV Assist suggestions remain suggestions until a person adopts or edits each field.

  6. 06

    Mark the preferred path

    Use Path on the timeline to pick the useful action sequence. Do not include steps labeled Redundant or Erroneous. A non-Unclear outcome needs a preferred path. If you intentionally reorder steps, select Counterfactual order and explain why.

  7. 07

    Save, submit, and review

    Choose Save draft to keep unfinished work, or Submit & next after confirming the boundary and all required labels. A submitted annotation is locked; an account with review permission can Accept review or Reopen it for correction.

  8. 08

    Compare and inspect quality

    Use Path comparison to compare eligible Episodes with the same intent category and target, then record Prefer A, Prefer B, Equivalent, or Insufficient evidence. A reviewer-capable account can open Human quality to inspect agreement in intent, outcome, step labels, and preferred paths.

What submission requires

Confirm the boundary; complete intent category, target, and confidence; choose an outcome; label every semantic step. Unless the outcome is Unclear, select outcome evidence and a preferred path. Reordered paths need a reason. Submitting does not itself train or deploy a model.

LEARNING / 03

Data standards and dataset versions

The learning pipeline has distinct records, eligibility rules, and a reproducible export. This is the contract to check before treating activity as reusable model data.

Data layers and their purpose
LayerRequired structureHow to interpret it
Activity eventSchema v1: record ID, timestamp, session, action, actor, source, provenance, trace, classification, context, input, and result.An observed action with sanitized evidence. It is not a task label or proof that an AI action was approved.
EpisodeVersioned segmentation policy; source environment, project and session identifiers, time window, ordered steps, lineage, and attention flags.A candidate task boundary. Semantic actions and observer actions can be inspected separately; split, merge, and exclusion are recorded as overlays.
Jev suggestion (optional)jev-episode-assist/1.0.0, evidence fingerprint, model, proposed intent and outcome, evidence steps, semantic step values, and confidence.Jev's proposed labels are stored separately for human review. They are not dataset labels.
Human annotationTaxonomy category, target and constraints, intent confidence, outcome and evidence, a label for every semantic step, preferred path, state, and revision.A person's interpretation of one Episode. Drafts can be incomplete; submitted labels must pass the required-field checks.
Dataset versionSemantic version, manifest, eligible Episodes, preference labels, exclusions, train/validation/test assignment, and SHA-256 checksums after freeze.A fixed export for later evaluation or training work. Freezing records integrity; it does not retrain Jev automatically.

Jev-assisted human labeling

  1. 01

    Open a Runtime Episode

    With a Jev key configured, selecting an editable Runtime Episode loads a saved JEV Assist suggestion or generates one. Use Regenerate to request a fresh suggestion. Manual labeling remains available without Jev.

  2. 02

    Check the proposed evidence

    Jev proposes an intent, an outcome and, where supported, an evidence step, plus a value for each semantic step. The page shows confidence or insufficient-evidence indicators and links back to the recorded steps. For this request, Jev receives bounded action, actor, outcome, and step-kind metadata from at most 50 steps, not the raw prompt or IFC geometry.

  3. 03

    Make the human decision

    For each proposal, choose Adopt, Keep my label, or edit the field yourself. Confirm the Episode boundary and choose the preferred path manually; Jev Assist does not propose that path or submit the annotation.

  4. 04

    Submit the label

    The submitted human annotation is the dataset label. Jev suggestions stay in a separate local record, and submission can record agreement diagnostics. Frozen dataset exports include the human annotation, not the suggestion or a field-by-field adoption history.

Allowed annotation values

Human labeling vocabulary
FieldAllowed values or rule
Intent categoryIFC property, type, spatial, or relationship query; selection; viewer visibility or navigation; section; project; output; coordination review; or Unknown. The stored taxonomy uses version episode-labels/1.0.0.
Intent confidenceHigh, Medium, or Low, based on how clearly the recorded task supports the chosen intent.
OutcomeSuccess, Partial, Failure, or Unclear. A non-Unclear outcome must point to one or more evidence steps.
Step valueNecessary, Supporting, Redundant, Erroneous, or Unclear for every semantic step. Observer events can supply context without requiring step labels.
Path comparisonPrefer A, Prefer B, Equivalent, or Insufficient evidence. A preference for A or B needs a reason code.

Build and verify a version

  1. 01

    Start with eligible runtime data

    Use real Runtime Episodes with a known project fingerprint, an active boundary, and a submitted or reviewed annotation. Test or legacy Episodes, excluded or superseded Episodes, missing boundaries, and missing project identity are excluded. If multiple independent submitted or reviewed annotations exist, at least one must be reviewed before inclusion.

  2. 02

    Check labels and comparisons

    Inspect the submitted intent, outcome evidence, all semantic step labels, and preferred path. A comparison can enter the dataset only when both linked Episodes are eligible. Human quality reports agreement; its dashboard is not an automatic approval of every label.

  3. 03

    Create a draft

    In Dataset versions, enter a new MAJOR.MINOR.PATCH value, such as 1.0.0, and click Build draft. This operation requires dataset publishing permission. Select the draft to inspect its manifest, Episode and preference counts, excluded count, and split counts.

  4. 04

    Inspect the split and exclusions

    The app deterministically groups by project fingerprint, session, and intent category before assigning approximately 80% train, 10% validation, and 10% test buckets. This keeps a related project/session/intent group in one split. The draft shows the exclusion count; detailed reasons appear in exclusions.json after export.

  5. 05

    Freeze and export

    Click Freeze version once the manifest and counts match the intended cohort. Then export manifest.json, episodes.ndjson, preferences.ndjson, exclusions.json, and checksums.sha256. Verify the SHA-256 values when transferring the files.

Files in a frozen dataset version
FileContents
manifest.jsonDataset name and version, status, policy versions, created/frozen metadata, counts, split totals, and checksums.
episodes.ndjsonOne eligible Episode per line, with selected step fields, a human annotation, split label, and hashed project/session identifiers.
preferences.ndjsonPairwise path choices whose two Episodes are both in this version.
exclusions.jsonEpisode IDs omitted from this version and the reason codes for each omission.
checksums.sha256SHA-256 hashes for the Episode, preference, and exclusion files; compare these with the manifest after transfer.

Versioned provenance

The manifest records episode-segmentation/1.0.0, episode-labels/1.0.0, and activity-log/1, plus counts and split totals. Exported Episodes use hashes in place of raw project and session IDs.

Privacy boundary

The log sanitizer replaces sensitive fields with presence markers, limits stored text and arrays, and runs in the client and local service. Raw Activity Logs remain local; dataset exports contain selected step and annotation fields. Review exports before sharing them.

Eligibility is specific

A single submitted human annotation can qualify; independent review is not required for every Episode. If more than one independent submitted or reviewed annotation exists, at least one must have reviewed status. The builder does not resolve disagreements automatically. Freeze makes a version immutable; corrections belong in a new version.

REFERENCE / 01

Important boundaries

These constraints help you interpret an agent response and choose the right application mode.

One platform action per request

A request such as “rename the project and export it” is outside the single-action workflow. Ask for each operation separately.

Project-grounded targets

Jev chooses only from present models, properties, tests, clashes, and issues. A missing target follows a validation error path.

IFC semantics are required

GLB and glTF can be viewed and coordinated geometrically, but they cannot supply IFC property or spatial relationship queries.

No source IFC rewrite

Coordination edits change the SophonBIM project, not the imported source files. Jev cannot overwrite a source IFC or email stakeholders.

AI needs the local service

Static builds cannot call Jev or DeepSeek, write Activity Logs, or publish labeled datasets. API keys may invoke paid external services.

Human-labeled iteration

Eligible submitted or reviewed annotations can become frozen datasets. Automatic training, deployment of a new model, and automatic adoption of suggestions are not implemented.

Data-size boundary

Large IFC context can be uploaded to the local service temporarily for an AI request. A single semantic IFC model above 32 MiB is rejected before a paid AI call. Accuracy is probabilistic; verify important results in the workspace.

REFERENCE / 02

When something stops

Start with the visible message, then check the current project and service state.

Common issues
What you seeWhat to check
Jev is unavailableUse the desktop app or npm start. Open Workspace account and add a Jev key after replacing any public demo password.
Parameter extraction failsAdd a DeepSeek key for compound filters or free-form fields. Check that the prompt names properties or targets present in this project.
